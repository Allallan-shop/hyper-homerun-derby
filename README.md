## 起動方法

Node.js 22以降を推奨。リポジトリを取得して以下を実行。

```bash
npm install
npm run dev
```

Viteが表示するローカルURLをPCブラウザで開きます。ボールが打撃位置まで近づくタイミングで、マウスを左右に動かし左クリックを長押しします。

```bash
npm run test
npm run build
npm run preview
```

`npm run test` はNode.js 22のTypeScript strip-types機能を使ったルール回帰試験です。**この変更セットは現時点で依存取得・実ゲーム動作検証が未完了です**。テストの存在をPASSの根拠にしないでください。

## プレイと設計

- タイトル → ステージ選択兼強化 → 対戦 → 通しリザルトの4画面。
- 仮の通常3ステージ。球数・必要HR・球種抽選比率・登場投手はデータ駆動。後から自由に増減可能。
- 投球は現実的な球、魔球、見た目の妨害を組み合わせる。縦は見た目だけ、判定は連続x座標＋タイミング。
- 原作寄りのカーソル追従遅延と長押しスイング、ポイントでパワー／ミート／スピードを強化。
- クリアタイムは1ステージ開始から最終面終了までの実経過時間。ハブ画面や再挑戦も含む。
- 1回のプレイにおける実打撃成績から5軸レーダーを生成。結果を正方形PNGとして出力。
- PCではPNGコピー → Xの投稿画面 → Ctrl+V。スマホは環境が対応していればOS共有。すべての環境でのワンタップ投稿は保証しません。
- セーブ・アカウント・ランキング・サーバーはありません。リロードすると進行が失われます。
- 将来の高難易度はモードの設定を追加・有効化してから使います。現状は**オフ**で、完成必須ではありません。

## 設定と画像／音声の差し替え

- `public/config/game-content.json`：モード、ステージ、球種と抽選重み、投手、強化、シェア文章。
- `public/config/assets.json`：ゲーム内で参照する画像・ボイス・BGM・効果音の論理IDと相対パス。
- `public/assets/`：ユーザーが権利を持つPNG/音声等を置く場所（今は空のため図形・無音で動く設計）。

画像・音声のパスが空なら、元のプログラムを変更せずに幾何学的な代替表示／無音で進行します。画像ID・ボイスIDは対応する投手設定で選べます。設定を書き換えたら再ビルドします。

## Human Review R2：野球らしい操作と左打ち

初回Human Reviewではステージ進行・タイマー・リザルト等の基本フローは維持可能と判断されましたが、打席が広すぎる／球が遅い／打球の追跡がない／ミートの芯と表示がずれる、という**野球ゲームとしての根本課題**が指摘されました。

このDraft PRのR2改修候補では以下を実施：
- **左打ちがデフォルト**（`public/config/game-content.json` の `gameplay.defaultBattingSide: "left"`）。打者はホームプレートの右側（画面の一塁側）に立つ想定。
- 将来の右打ちでは `defaultBattingSide` を `"right"` に変更すると、打者位置・バットの持ち手・画像の向きが左右反転します。**ゲーム内で左右を選ぶ画面や打席別アニメーションはまだ作っていません**。判定ロジックは両側で共通です。
- 打者の身体が画面端へ走らないよう、身体を打席内に固定し、バットの目標移動と投球の着弾位置をホームプレート付近の小さな連続x座標範囲に制限。
- ネイティブのマウスカーソルを隠し、緑色のバット芯／白い照準マークを**実際の当たり判定中心と一致**させる。追従遅延自体は原作準拠で残す。
- 球速を初期段階から上げ、チェンジアップを相対的に遅くして緩急を出す（具体値は仮）。
- バットに当たった全打球をカメラ追跡モードで**最後の着弾点まで表示**し、結果を表示した後に次の投球へ進む。
- 残り投球の各球をアイコン表示：白＝未消化、赤＝HR、灰＝その他。規定球数は引き続きステージ設定から取得。
- 生成済みのGPTimage仮アセット（ドーム球場、左向き打者、投手、ボール）を`public/assets/`に配置し、`public/config/assets.json`で相対パスを設定すれば、コード変更なしに試せる構造。**画像のバイナリはGitHubのこのPRには未追加**。追加しない場合は図形による代替表示。
